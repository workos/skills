# AUTH-6793 implementation notes

## Behavior delivered

- React and vanilla browser SDKs: recommend the documented `window.origin` redirect default (e.g. `http://localhost:5173`), with no unnecessary `/callback` route or redirect env variable.
- Explicit custom redirects remain supported. Application code must supply the option; effective SDK URL, saved registration, and a reachable destination that initializes the SDK must agree. Parsing, env-file presence, and grep hits are not integration validation. No blanket path/trailing-slash ban or silent normalization.
- React Router selection now inspects configuration, imports, routes, request-time execution, and deployment. Library/data/declarative client apps and static framework SPA deployments use React client guidance. Supported server framework use retains a registered `authLoader()` callback, server secrets, and configuration precedence. Contradictory signals require clarification, not dependency priority or forced migration.
- Vite and CRA examples show actual option consumption; custom bundlers require inspection rather than an invented prefix. Secrets stay server-only. CORS uses the requesting app's origin, not the redirect path.
- Shared Sign-out URI, separate SDK-backed Initiate login URI, environment targeting, preserve/merge, dry-run/read-back, and manual fallback remain in place.
