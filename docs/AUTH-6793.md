# AUTH-6793 implementation notes

## Behavior delivered

- React and vanilla browser SDKs: recommend the documented `window.origin` redirect default (e.g. `http://localhost:5173`), with no unnecessary `/callback` route or redirect env variable.
- Explicit custom redirects remain supported. Application code must supply the option; effective SDK URL, saved registration, and a reachable destination that initializes the SDK must agree. Parsing, env-file presence, and grep hits are not integration validation. No blanket path/trailing-slash ban or silent normalization.
- React Router selection now inspects configuration, imports, routes, request-time execution, and deployment. Library/data/declarative client apps and static framework SPA deployments use React client guidance. Supported server framework use retains a registered `authLoader()` callback, server secrets, and configuration precedence. Contradictory signals require clarification, not dependency priority or forced migration.
- Vite and CRA examples show actual option consumption; custom bundlers require inspection rather than an invented prefix. Secrets stay server-only. CORS uses the requesting app's origin, not the redirect path.
- Shared Sign-out URI, separate SDK-backed Initiate login URI, environment targeting, preserve/merge, dry-run/read-back, and manual fallback remain in place.

## PR49 paraphrase follow-up

Addressed [review comment 4137775514](https://github.com/workos/skills/pull/49#discussion_r4137775514). The natural CRA fixture (including “register the full redirect URL”) reproduced a **94 instead of 100** score before this fix; it now scores **100** without requiring the case's exact phrases.

- Added optional `expected.unorderedRequirements`, an array of `{ anyOf: string[], noneOf?: string[] }`. Each group represents **one required meaning**, not optional extra credit: one equivalent affirmative phrase must match, with no negated alternative or asserted `noneOf` contradiction. The first alternative is the stable signal label. All 29 original setup signals remain as first alternatives; original technical params, prompts, imports, env vars, methods, anti-patterns, hallucination checks, and SDK guidance are unchanged.
- Phrase matching requires **every word**, in order within one clause, allowing up to three intervening words per gap. This accepts inserted articles/qualifiers; explicit alternatives cover different wording such as “allowlist the entire redirect URL.” Punctuation and conjunction boundaries prevent assembling evidence from unrelated clauses. Quoted prose, Markdown blockquotes, and questions do not count as recommendations. Extra denial words reject an alternative, but negatives that are part of the expected phrase (e.g. “no server callback” or “server callback is not required”) remain valid. Authored `noneOf` patterns catch specific opposite advice, including registering only an origin for the deliberate custom redirect, a callback path for CORS, or creating a server callback in a static SPA.
- **Weights and defaults:** groups share the existing 15-point parameter dimension, one group per former setup signal. The denominator remains `params.length + unorderedRequirements.length`; multiple alternatives do not multiply credit. No new score dimension, report schema, or error category: missing/contradicted groups contribute to `wrong_params`, and diff summaries use the same matcher and list missing group labels. Omitted/empty optional fields preserve legacy scores and categories exactly. Causal flow scoring still applies its original ordering penalty. Compared with the previous case-only fix, weights are unchanged but lexical acceptance is intentionally different; no claim of unchanged model calibration or improved model behavior.
- **Validation/compatibility:** both YAML-loading paths validate the opt-in shape and nonempty phrase lists. Tests cover loader round trips, malformed field rejection, report-summary JSON round trips, and legacy absent/empty-field equivalence. Existing report/scorer/runner/diff tests pass unchanged.
- **Coverage:** retained all 342 original setup permutations and omission checks; added hand-written natural paragraphs for all 29 setup meanings, their reordering and omission tests, and incorrect/quoted/negated/contradictory/cross-clause examples. Incorrect CRA registration explanations lose credit through the real scorer and error categorizer, not just the matcher. Existing SSO causal-flow reversal still loses credit.
- **Limits:** this is a conservative English lexical heuristic, not general natural-language inference. It does not recognize arbitrary synonyms, grammar, sarcasm, or all contradictions. Supported alternatives and contradiction phrases are explicit; unlisted paraphrases or complex clauses may still under-score, and keyword mentions can still over-score outside the covered cases. Technical params retain their prior exact normalized matching. Offline checks do not establish semantic correctness, model recommendations, or live authentication.
